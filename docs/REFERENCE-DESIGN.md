# V3.5 reference design

Heavenly Axis keeps the HUD canvas visible while the user selects and adjusts a control. A compact toolbar holds selection and session actions. Quick Edit keeps the active transform, its value and its affordance together. The full workspace holds Layers, Groups, Profiles, Settings and Help. Native retained Roblox instances let the editor keep one owner for gestures and update the selection without rebuilding the workspace.

The public sources below were inspected as text at the listed commits. The release keeps its native editor components and bundles a pinned Lucide glyph subset rendered with Roblox GUI primitives. The UI reference packages, their loaders, and their analytics are outside the runtime. [Icon implementation and attribution](ICON-SYSTEM.md)

## Mobile editor patterns

- **Canvas and inspector.** Lightroom mobile groups transform controls in a secondary tool view while keeping the photo in view. Procreate reveals transform tools with a clear selection boundary and direct handles. Keep the HUD as the largest surface, and keep the current transform, its value and the relevant reset near the selection. [Lightroom workspace](https://helpx.adobe.com/lightroom/mobile/get-started/workspace-overview.html), [Lightroom crop and geometry](https://helpx.adobe.com/lightroom/mobile/crop-and-transform/crop-photos.html), [Procreate transform interface](https://help.procreate.com/procreate/handbook/transform/transform-interface-gestures)
- **Toolbar and choices.** Put related commands together and keep Save and Done distinct. Use text for unfamiliar actions and move secondary commands to overflow as width shrinks. In Select Through, distinguish the whole control, the exact layer and the containing bar. Long-press can open this contextual choice. Ordinary taps and drags remain direct. [Apple toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars), [Apple context menus](https://developer.apple.com/design/human-interface-guidelines/context-menus), [Apple gestures](https://developer.apple.com/design/human-interface-guidelines/gestures/)
- **Touch and motion.** Use compact icons inside larger independent hit targets. Hold a consistent heading, body and metadata hierarchy. Use motion for short feedback, preserve reduced-motion behavior, and keep toasts clear of the canvas affordances. [Roblox adaptive design](https://create.roblox.com/docs/production/publishing/adaptive-design), [Roblox UI and UX design](https://create.roblox.com/docs/production/game-design/ui-ux-design)

## Roblox implementation constraints

- Use `ScreenInsets` and `GuiService:GetInsetArea()` to fit interactive chrome inside Roblox and device safe regions. `GuiBase2d.AbsolutePosition` and `InputObject.Position` share Core UI inset coordinates. Map positions to each overlay parent's local origin before drawing handles or controls. Clamp using usable bounds and test with short landscape, portrait and notched viewports. [ScreenGui](https://create.roblox.com/docs/reference/engine/classes/ScreenGui), [GuiService](https://create.roblox.com/docs/reference/engine/classes/GuiService#GetInsetArea), [GuiBase2d](https://create.roblox.com/docs/reference/engine/classes/GuiBase2d)
- Use explicit `LayoutOrder` and measured scrolling content. `UIListLayout` governs sibling position and rotation and flex can change size. `UIGridLayout` controls cell geometry. A HUD control wrapper or containing bar can remain a valid selection while a particular direct transform is unavailable. Offer the supported target or operation beside the blocked control. [List and flex layouts](https://create.roblox.com/docs/ui/list-flex-layouts), [Grid and table layouts](https://create.roblox.com/docs/ui/grid-table-layouts), [Position and size](https://create.roblox.com/docs/ui/position-and-size), [Scrolling frames](https://create.roblox.com/docs/ui/scrolling-frames)
- Keep hit ranking, grip movement, tap, pinch, resize, angle and opacity in the current event-driven input architecture. Limit reviewer claims to the observed environment. Geometry simulations can verify layout and pointer transitions. Native clipping, hit delivery and displayed text still require Roblox rendering and hardware checks. [Roblox device simulation](https://create.roblox.com/docs/studio/testing-modes#device-simulation)
